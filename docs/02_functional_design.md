# 機能設計書

## 1. 対象機能の概要
おみくじAPIを高可用・自動スケーリング構成で稼働させるAWSインフラ(VPC/ネットワーク・ALB・Auto Scaling)。

## 2. アーキテクチャ概要図
```
                         Internet
                            │
                        (0.0.0.0/0:80)
                            │
                    ┌───────▼────────┐
                    │  ALB (public)   │  複数AZのpublic subnetに配置
                    └───────┬────────┘
                     80/HTTP │ (ALB SGのみ許可)
        ┌───────────────────┼───────────────────┐
        │                   │                   │
 ┌──────▼──────┐     ┌──────▼──────┐     (Auto Scaling: 2〜4台)
 │ EC2 (AZ-a)   │     │ EC2 (AZ-c)   │     private subnetに配置
 │ Amazon Linux │     │ Amazon Linux │     SG: ALBからの80番のみ許可
 │ 2023 / t2.micro│   │ 2023 / t2.micro│
 └──────┬──────┘     └──────┬──────┘
        │ outbound 80/443 (NAT経由)             │
        └───────────────┬───────────────────────┘
                    ┌────▼─────┐
                    │ NAT GW    │  単一構成(コスト優先)
                    │ (public)  │
                    └────┬─────┘
                    ┌────▼─────┐
                    │   IGW     │
                    └──────────┘
```

## 3. 主要コンポーネント
| コンポーネント | 役割 | 実装モジュール |
|---|---|---|
| VPC / サブネット / フローログ | ネットワーク基盤(public/private、複数AZ) | `modules/vpc` |
| IGW / NAT Gateway / ルートテーブル | インターネット疎通(単一NAT構成) | `modules/vpc-routing` |
| ALB / ターゲットグループ / リスナー / SG | 負荷分散、80番ポートのみ許可 | `modules/alb` |
| Launch Template / Auto Scaling Group / スケーリングポリシー / SG | APIサーバの起動・自動増減 | `modules/asg-api` |

## 4. データフロー
1. クライアントがALB(public subnet, 複数AZ)へHTTP:80でアクセスする。
2. ALBがALB用SG(80番のみ許可)を通過し、ターゲットグループ経由でprivate subnet上のEC2(APIサーバ)へ80番ポートで転送する。
3. APIサーバ用SGはALBのSGからの80番ポート通信のみ許可し、インターネットからの直接アクセスは拒否する。
4. APIサーバはソフトウェアインストール等のため、NAT Gateway(単一構成)経由でインターネットへアウトバウンド通信(80/443)を行う。
5. CloudWatch(ASGのCPUUtilizationメトリクス)を用いたターゲット追跡スケーリングにより、CPU使用率70%を境に2〜4台の範囲でEC2インスタンス数を自動調整する。

## 5. 依存する既存モジュール
- `modules/vpc`(既存): VPC本体・サブネット・フローログ。
- 本スプリントで新規追加: `modules/vpc-routing`・`modules/alb`・`modules/asg-api`。

## 6. 機密情報の扱い
- 本機能では機密情報(パスワード・APIキー等)をTerraformで生成・管理しない。
- APIサーバのユーザデータスクリプトは開発チームから提供される内容をそのまま使用し、認証情報等のハードコードが無いことを事前に確認する。
- Terraform側ではユーザデータの中身(スクリプト)のみを参照し、機密情報の生成・管理は行わない。
